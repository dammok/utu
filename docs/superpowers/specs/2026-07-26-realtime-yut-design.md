# 실시간 윷놀이 — 기획서

- **작성일**: 2026-07-26
- **상태**: 설계 확정, 구현 계획 대기
- **산출물**: 웹 브라우저용 단일 페이지 게임

---

## 1. 무엇을 만드는가

에너지가 차는 대로 윷을 던져 결과를 소비하며, 게임이 진행될수록 빨라지는 압박 속에서 말 4개를 먼저 완주시키는 **1인용 실시간 윷놀이**.

원작 윷놀이는 턴제지만, 이미 **던지기와 말 이동이 분리된 구조**를 가지고 있다(윷·모가 나오면 한 번 더 던지고, 나온 결과들을 모아 말에 배분한다). 이 게임은 그 구조를 그대로 두고 "언제 던질 수 있는가"만 턴에서 에너지로 바꾼다. 규칙을 비틀지 않고 실시간이 얹히는 이유다.

## 2. 목적과 제약

| 항목 | 결정 | 설계에 미치는 영향 |
|---|---|---|
| 목적 | 포트폴리오·데모 | 코드 구조보다 완성도가 결과물의 본체 |
| 평가 기준 | 첫인상·시각적 완성도 | 연출·손맛·사운드에 자원을 집중 |
| 노출 경로 | 링크 공유 + 직접 시연 | 온보딩과 연출을 모두 충족해야 함 |
| 핵심 재미 | 속도감·손이 바빠지는 감각 | 결과를 쌓아두는 전략형과는 반대 방향 |
| 세션 길이 | **목표 없음 (자연 진행)** | 게임 상태가 길이를 결정한다 |
| 플랫폼 | 모바일 필수 | 터치 조작·성능 예산이 1급 제약 |
| 대전 상대 | AI (온라인 없음) | 동시성 판정에 권위 서버가 불필요 |

**비목표(Non-goals)**: 온라인 멀티플레이, 계정·랭킹·수익화, 로컬 2인 플레이. 첫 버전 범위에서 명시적으로 제외한다.

## 3. 핵심 루프

```
에너지 자동 충전 (상한 3칸)
      │  1칸 소모
      ▼
   윷 던지기 ──── 윷·모 → 상한 무시 보너스 던지기
      │
      ▼
  결과 큐에 적립 (국면에 따라 만료)
      │  에너지 소모 없음
      ▼
 결과 + 말 선택 → 이동
      │
      ▼
   상대 말 잡기 → 상한 무시 보너스 던지기
```

**보너스는 한 종류로 통일한다.** 윷·모도, 잡기도 모두 "상한을 무시하는 즉시 던지기 1회". 규칙이 늘지 않고, 에너지가 꽉 찼을 때 잡아도 보상이 증발하지 않는다.

## 4. 국면 구조

게임은 세 국면을 거치며 가속된다. 전환 기준은 **시간이 아니라 진행도**다.

| 국면 | 진입 조건 | 충전 | 결과 만료 | 방치 허용 |
|---|---|---|---|---|
| 도입 | 시작 | 6.5초 | 없음 | 19.5초 |
| 전개 | 양쪽 합쳐 2말 완주 | 5.0초 | 15초 | 15.0초 |
| 종반 | 양쪽 합쳐 4말 완주 **또는** 어느 쪽이든 3말 완주 | 3.8초 | 10초 | 11.4초 |

### 진행도 기준을 쓰는 이유

- 접전이면 저절로 길어지고, 승부가 기울면 빨리 끝난다
- 잡기로 판이 되돌아가면 종반이 늦춰져, 극적인 순간이 타이머에 잘리지 않는다
- 종반은 **항상** 승부가 무르익은 시점에 온다. 시간 기준이라면 3:0으로 기운 판에서도 광란이 와서 허무했을 것이다

### 이 구조가 동시에 해결하는 것

- **온보딩** — 도입 구간이 느려 링크로 처음 연 사람도 배운다. 튜토리얼 팝업이 필요 없으므로 직접 시연도 방해받지 않는다
- **모바일 피로** — 진짜 바쁜 구간이 후반에만 몰린다
- **데모 서사** — "점점 빨라진다"가 설명 없이 전달되고, GIF로 잘라도 대비가 보인다

**예상 길이**: 평균 2.5~3분, 접전 시 5~6분, 일방적이면 1.5분. 고정값이 아니라 범위로 둔다.

## 5. 속도 수치의 근거

충전 속도는 감이 아니라 **인간 반응 하한**에서 역산했다. 초보의 한 사이클:

| 단계 | 소요 |
|---|---|
| 던지기 클릭 | 0.3초 |
| 모션 + 결과 인지 | 0.65초 |
| 판단 (내 말·상대 말 위치, 잡기 가능 여부, 지름길 여부) | 3~5초 |
| 말 클릭 (모바일 터치 오차 포함) | 0.4초 |
| 이동 결과 확인 | 0.4초 |
| **합계** | **약 6초** |

도입 국면의 6.5초는 이 값을 그대로 반영한다. 종반의 3.8초가 더 빠른 것은 의도된 것이다 — **종반에 도달한 플레이어는 이미 던지기를 20회 넘게 했고 판 구조와 도개걸윷모를 몸으로 익힌 상태라 더 이상 초보가 아니다.** 난이도 곡선이 학습 곡선을 따라가므로 별도의 적응형 로직이 필요 없다.

**측정된 전제**: 한 판에 필요한 던지기는 1인당 평균 29회, 말 이동 33회 (프로토타입 300게임 자동 대전 실측).

### 에너지 상한이 3칸인 이유

상한의 정체는 "몇 번 모을 수 있나"가 아니라 **"손을 놓아도 손해가 안 나는 시간"**이다(상한 × 충전 = 방치 허용).

| 상한 | 도입 | 종반 | 판정 |
|---|---|---|---|
| 1칸 | 6.5초 | 3.8초 | 고민할 때마다 손해 — 판단 자체가 처벌받는다 |
| 2칸 | 13.0초 | 7.6초 | 완충이 얕아 한 수 오래 고민하면 바로 낭비 |
| **3칸** | **19.5초** | **11.4초** | **판단 지연을 흡수하면서도 방치는 처벌한다** |
| 4칸 | 26.0초 | 15.2초 | 종반에도 여유가 남아 압박이 생기지 않는다 |

3칸은 **판단하느라 늦어진 만큼을 흡수하는 완충 장치**다. 부수 효과로 3연속 던지기가 가능해 결과가 한꺼번에 쏟아지는 "터지는 순간"이 만들어지고, 게이지 3칸은 폰 화면에서 세지 않고 읽힌다.

## 6. 게임 규칙 (원작 준수)

### 판

29칸. 외곽 20칸 + 지름길 8칸 + 중앙 1칸("방").

- **외곽**: 출발(우하) → 우변 → 우상 모서리 → 상변 → 좌상 모서리 → 좌변 → 좌하 모서리 → 하변 → 골
- **지름길 A**: 우상 모서리 → 중앙 → 좌하 모서리
- **지름길 B**: 좌상 모서리 → 중앙 → 골
- 모서리에 **정확히 멈추면** 지름길로 진입한다. 지나치면 외곽을 유지한다
- 지름길 A로 진입한 뒤 중앙에 **정확히 멈추면** 최단로(중앙 → 골)로 전환한다

완주 거리: 외곽 20칸 / 지름길 16칸 / 중앙 경유 최단 11칸.

### 윷 결과

윷가락 4개, 배(평평한 면)가 나올 확률 0.6. 한 가락에 백도 표식.

| 결과 | 조건 | 이동 | 비고 |
|---|---|---|---|
| 백도 | 배 1개 (표식 가락) | -1 | 대기 말·출발점 말은 사용 불가 |
| 도 | 배 1개 | 1 | |
| 개 | 배 2개 | 2 | |
| 걸 | 배 3개 | 3 | |
| 윷 | 배 4개 | 4 | 보너스 던지기 |
| 모 | 배 0개 | 5 | 보너스 던지기 |

실측 분포(20만 회): 도 11.6% / 개 34.5% / 걸 34.5% / 윷 13.0% / 모 2.6% / 백도 3.9%.

### 그 외

- **말 4개**. 모두 골인하면 승리
- **업기**: 같은 칸의 아군 말은 한 뭉치로 함께 이동한다
- **잡기**: 상대 말이 있는 칸에 도착하면 그 말들은 대기로 돌아가고, 잡은 쪽은 보너스 던지기 1회를 얻는다
- **완주**: 골을 넘어서도 완주로 인정한다
- **백도 제한**: 대기 말과 출발점(이동 0칸) 말은 백도를 쓸 수 없다

## 7. 동시성 판정

브라우저 JS는 단일 스레드이므로 **진짜 동시는 존재하지 않는다.** 두 입력은 이벤트 큐에 순서대로 들어가고 반드시 선후가 갈린다. 온라인 멀티를 비목표로 둔 결정이 여기서 권위 서버의 필요를 없앤다.

**규칙: 먼저 입력된 쪽이 이긴다(선착순).** "이동 중인 말은 못 잡는다"나 "잡기 우선" 같은 특수 규칙은 넣지 않는다 — 설명할 규칙이 늘고 "왜 안 잡혔지?"라는 혼란만 만든다.

설계 과제는 **진 쪽의 체감**이다. 네 가지를 강제한다:

1. **결과 칩을 소모하지 않는다.** 이동이 무효화되면 칩은 큐에 남고 선택 상태만 해제된다. 자원이 아무것도 못 하고 사라지면 억울함만 남는다
2. **무효화를 명시적으로 알린다.** "잡혔습니다 — 간발의 차!" 같은 즉각 피드백. 침묵하면 버그로 인식되고, 알려주면 드라마가 된다
3. **AI 판단 지연 하한 0.4초.** AI는 이론상 0ms에 반응해 경합에서 항상 이긴다. 이는 난이도 값이 아니라 **공정성 하한**이므로 어려움 난이도에서도 내리지 않는다
4. **반대 경우는 처리하지 않는다.** 내가 가려던 칸에 상대가 먼저 들어오면 내 이동은 여전히 유효하고 오히려 내가 잡는다. 손해가 아니라 이득이다

### 관통 원칙

> **상태는 입력 순간 즉시 확정되고, 애니메이션은 결과의 사후 표현일 뿐이다.**

던지기 결과도, 말 이동도 이 원칙을 따른다. 애니메이션 재생 중에도 말의 위치는 이미 새 칸이므로 그 사이 들어온 잡기는 새 위치로 판정된다. **애니메이션이 게임 규칙에 영향을 주지 않으므로 화면과 상태가 어긋나는 버그가 원천적으로 생기지 않는다.**

## 8. 연출

### 논블로킹 (필수 제약)

폴리싱 단계에서 발견하면 이미 늦으므로 설계 시점에 못 박는다.

- 던지기 모션 **250ms**, 전체화면 오버레이 폐지 → **보드는 항상 보인다**
- 결과는 모션 완료를 기다리지 않고 즉시 큐에 적립된다
- 잡기·이동·국면전환 이펙트는 게임 진행을 멈추지 않는다. 보너스 연쇄로 모션이 겹쳐 재생되어도 입력이 막히지 않는다
- 종반 충전 3.8초 기준 던지기 모션 점유율 6.6%

**긴 모션은 손맛이 아니라 지연이다.** 손맛은 입력→반응의 즉각성, 결과 확정의 임팩트, 보상감에서 나오며 셋 다 250ms로 충분하다.

### 동물 연출 (고증 기반)

도·개·걸·윷·모는 원래 **가축의 크기·속도 순서**를 딴 이름이다.

| 결과 | 동물 | 칸 수 |
|---|---|---|
| 도 | 돼지 | 1 |
| 개 | 개 | 2 |
| 걸 | 양 | 3 |
| 윷 | 소 | 4 |
| 모 | 말 | 5 |

**말이 이동할 때** 해당 동물이 판을 달린다. 던지기가 아니라 이동에 붙이는 이유:

- 이동은 플레이어가 원하는 타이밍에 하므로 시간 압박이 없다
- 여러 말이 동시에 달려도 서로 막지 않는다
- 던질 때는 아직 어디에 쓸지 모른다. "이 결과가 무슨 뜻인가"를 보여줄 자리는 이동이다

이동 거리와 동물의 속도가 시각적으로 일치하므로, 처음 보는 사람이 도개걸윷모를 외우지 않고도 **"말이 나왔네 = 많이 가네"**를 즉시 이해한다. 4장의 난이도 곡선과 함께 온보딩을 이중으로 해결한다.

진영은 **청군 호랑이 / 홍군 곰**. 한국적이면서 실루엣 대비가 확실하다.

### 국면 전환 연출 (필수)

화면 톤 변화 + 배너 + 사운드. **이것이 없으면 4장의 국면 구조는 "일관성 없는 게임"으로 느껴진다.** 선택 사항이 아니라 설계의 필수 부품이다.

### 배경

숲 테마. 한지·먹 미감의 전통 윷판 위에 숲의 색조를 얹되, 윷판의 기하 구조(정사각형 + 대각선)는 훼손하지 않는다 — 판 구조가 읽히지 않으면 실시간 판단이 불가능해진다.

## 9. 판단 비용 절감

충전 속도만큼 중요하다. **속도를 올리고 싶으면 속도를 올릴 게 아니라 판단 비용을 낮춰야 한다.** 아래를 잘 만들면 사이클 하한이 6초에서 4.5초까지 내려가고 그만큼 조일 여지가 생긴다.

종반 충전 3.8초는 **두 효과가 겹친 결과**다. 학습으로 6초 → 4.5초, UI 지원으로 4.5초 → 약 3.5초. 어느 한쪽만으로는 3.8초가 성립하지 않으므로, **이 장의 UI 항목은 편의 기능이 아니라 종반 속도의 전제 조건이다.** 구현에서 빠지면 종반 충전값을 함께 늦춰야 한다.

- 결과 칩 선택 시 **이동 가능한 말과 도착 지점을 즉시 표시** — 머릿속 계산을 화면이 대신한다
- **잡을 수 있는 수는 별도 강조** — 가장 중요한 선택을 0.2초에 인지시킨다
- 같은 값의 결과는 묶어서 표시 (`개 ×3`)
- 데스크톱: 말 1~4 숫자키 단축키
- 모바일: 터치 타깃 44px 이상

## 10. 모바일

- 세로 화면 우선. 보드가 상단, 조작이 하단 엄지 도달 범위
- 던지기 버튼은 한 손 엄지로 누를 수 있는 위치에 고정
- 터치 타깃 44px 이상, 인접 말 사이 간격 확보
- hover가 없으므로 도착 지점 미리보기는 **칩 선택 시점에** 표시한다(데스크톱은 hover 추가)

## 11. 성능 예산

중저가 안드로이드 기준 **60fps 유지**. 실시간 게임은 프레임이 떨어지면 그대로 무너진다.

- 초과 시 감축 순서: 파티클 → 그림자·블러 → 배경 디테일
- 게임 상태 갱신과 렌더링을 분리해, 렌더가 무거워져도 규칙 판정은 정확도를 유지한다

## 13. 기존 프로토타입 처리

`index.html`에 동작하는 프로토타입이 있다(규칙 17종 검증, 400게임 자동 대전 통과). 재사용 여부는 구현 계획에서 결정하되, 현 시점의 판단은 다음과 같다.

**유지 가능**: 판 정의(29칸 좌표·경로 4종), 윷 확률, 이동·업기·잡기 규칙, 검증 스크립트.

**변경 필요**:
- 결과 만료 (없음 → 국면별 만료). 기획 초기에 "만료 없음"으로 정했다가 **속도감을 핵심 재미로 확정하면서 뒤집힌 결정**이다. 결과를 무한정 쌓으면 플레이어가 판단을 미루게 되고 그것이 속도감을 죽인다
- 잡기 보상 (에너지 +1 → 상한 무시 보너스 던지기). 에너지가 꽉 찼을 때 보상이 증발하는 문제
- 에너지 충전 (고정 2.6초 → 국면별 6.5/5.0/3.8초)
- 던지기 연출 (전체화면 오버레이 620ms → 논블로킹 250ms)
- 무효 입력 피드백 (없음 → 명시적 알림, 칩 미소모)
- AI 판단 지연 하한 0.4초 강제
- 모바일 레이아웃·터치 타깃
- 동물 연출·숲 테마 전면 신규

**폐기**: 전체화면 던지기 오버레이, 난이도 3단계(국면 구조가 난이도 곡선을 대신하므로 재검토 대상).

## 14. 열린 항목

구현 중 실측으로 확정할 값. 추측으로 확정하지 않는다.

- **국면별 충전값과 게임 길이 — 실측 완료, 조정 여부는 보류.**

  자동 대전 300게임 실측(양쪽 다 '보통' AI): 평균 게임 길이 **82.5초**, 1인당 던지기 **22.7회**.
  기획 시점 예상(2.5~3분, 던지기 29회)과 **불일치** — 실측이 예상보다 짧다.
  승률은 44~58% 사이에서 실행마다 변동하는데, 동일 AI끼리 붙이므로 정상 범위다.

  국면별 평균 체류 시간: 도입 60.6초 / 전개 11.8초 / 종반 10.1초.
  종반 도달률은 61%다 — 도입만 하고 끝나는 게임이 19.3%, 전개까지만 가는 게임이 19.7%다.

  이 수치가 드러낸 것: **"게임이 진행될수록 빨라진다"는 설계 의도가 실제로는 절반만 성립한다.**
  플레이 시간의 73%가 가장 느린 도입 구간이고, 5판 중 1판은 가속을 한 번도 겪지 않고 끝난다.
  원인은 충전 수치가 아니라 국면 전환의 기준 자체다 — 완주(골인)는 말이 판을 거의 다 돈 뒤에야
  일어나는 희소 사건이라, 완주 기반 트리거는 구조적으로 게임 막바지에만 발화한다. 임계값을
  낮춰도 정도만 달라질 뿐 이 구조는 바뀌지 않는다.

  대안도 측정했다: **전진율**(8말이 각자 경로에서 온 거리의 합 ÷ 8)을 국면 기준으로 쓰면 게임
  내내 매끄럽게 증가하고, 전진율 15%에서 전개로, 39%에서 종반으로 끊으면 시간이 대략 40/30/30
  으로 갈린다(300게임 중앙값 기준).

  **사용자 결정 (2026-07-26):** 국면 기준은 완주 기반의 **현재 설계를 유지**한다. 게임 길이
  82.5초를 조정할지 여부는 **UI 완성 후 직접 플레이해보고 판단**하기로 미뤘다. 두 결정 모두
  수치를 몰라서가 아니라 알고도 지금 손대지 않기로 한 것이다.

  이 결정을 다시 볼 때 알아야 할 것 두 가지. 첫째, **되돌리는 비용이 작다** — 전진율 기준으로
  갈아타려면 `game.js`의 `phaseOf` 한 함수만 바꾸면 되고, 나머지 코드는 국면 번호만 받아 쓰므로
  영향이 없다. 임계값(15% / 39%)도 이미 측정돼 있다. 둘째, **재검토 시점이 정해져 있다** —
  사람이 직접 플레이해본 뒤다. AI끼리의 82.5초와 사람이 겪는 82.5초는 체감이 다를 수 있고,
  그 차이를 확인하기 전에 수치를 건드리면 무엇 때문에 나아졌는지 알 수 없게 된다.

  부수 발견 — 승률 테스트의 허용 오차를 ±5%p에서 ±9%p로 넓혔다. 300게임 표준편차가 약
  2.9%p인데 ±5%p는 1.7σ뿐이라, 정상 구현도 약 9% 확률로 실패하는 flaky 테스트였다.

- 던지기 모션 250ms의 적정성 — 국면별 단축(350ms→200ms) 여부 포함 (미측정, 열린 채로 둠)
- 난이도 선택 UI 존치 여부 (미측정, 열린 채로 둠)
- 결과 만료 임박 시 경고 연출의 강도 (약하면 놓치고, 강하면 시야를 어지럽힌다) (미측정, 열린 채로 둠)
